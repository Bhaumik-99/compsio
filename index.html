How the Research Was Done

The agent pipeline, where it worked well, and where a human was needed.

The Research Agent

  • AI-powered research pipeline using web search across 100 apps
  • Automated querying of developer docs, API references, and auth pages
  • Structured data extraction into a normalized JSON schema
  • Pattern detection and statistical analysis across the full dataset
  • Built with Gemini (Antigravity IDE) as the orchestration layer

Data Sources Per App

  • Official developer documentation (primary source)
  • API reference pages and OpenAPI/Swagger specs
  • Developer blog posts and changelog entries
  • Community MCP server registries
  • Pricing pages for self-serve assessment

Where Humans Were Needed

  • Gated apps: DealCloud, PitchBook, Gladly — docs behind login walls
  • Ambiguous auth: judgment on primary vs. secondary methods
  • MCP verification: checking if MCP servers actually work
  • Self-serve nuance: distinguishing "free trial" from "free tier"
  • Newer platforms: fanbasis, Paygent, iPayX — sparse docs

Schema & Output

  • Each app produces 11 structured fields in JSON
  • Auth normalized to: OAuth2, API Key, Basic, Token, JWT, HMAC, None
  • Self-serve: free_tier, trial, paid_required, contact_sales
  • Buildability: ready, feasible, challenging, blocked
  • Evidence URLs and notes captured for every finding

Verification Methodology

  • 20 apps selected via stratified sampling (2 per category)
  • Each app manually verified by visiting official developer docs
  • Cross-checked: auth, self-serve, API type, breadth, MCP, buildability
  • First-pass accuracy was ~88%; verification loop improved it to 94%
  • Most common error: self-serve nuance (trial vs. free tier distinction)
  • Zero errors on well-documented apps (Stripe, GitHub, Slack)

Honest Limitations

  • Sherlock & Mermaid CLI are CLI tools, not APIs. "Blocked" is the correct finding.
  • PitchBook API details unverifiable without enterprise contract.
  • NotebookLM consumer API doesn't exist. Enterprise requires Google Cloud.
  • Paygent Connect has very limited public documentation.
  • MCP availability — community servers may be unmaintained.
  • Self-serve status can change. Data is current as of August 2026.
